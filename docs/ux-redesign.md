# UX改修 — 2026-09-20

## 利用者にとっての変更

ホームを青と白の検索画面へ変更し、「エリアから探す」「施設名で判定」の入口を分けた。記事冒頭にも判定へのリンクを置き、目次は折り畳んで本文を読み始めやすくした。

施設ページでは自分の車を判定するフォームを基本情報の直後へ移動。宮下公園北・390×844pxの確認では上端約13,225pxから約347pxになった。補助の人気車種一覧は初期表示を6件に制限した。

車種ページは世代・グレードと4項目の寸法を先に表示し、詳しい制限比較を折り畳む。駐車場候補のフィルタを一本化し、検索結果ゼロ件から絞り込みを解除できる。

## 判定条件と表示

- 車種・世代・グレードをURLで引き継ぐ。車種→エリア→駐車場、地図のリンク、現在地検索、マイカーの再訪に対応。
- マイカーにはグレードIDと表示名も保存する。旧データにIDがない場合は代表グレードと明示して再選択できる。
- グレードの寸法は読み取り専用の `/api/cars/[slug]/trims` で取得する。保存済み寸法だけを判定の根拠にしない。
- 不正・不一致の世代やグレードを代表グレードに置き換えない。通信失敗・切り替え時にも古い判定を残さない。
- `サイズ条件内` は空車を意味しない。未確認の寸法があればOKにせず要確認、既知の超過はNGを優先する。
- 判定の対象グレードと区画名・注記を表示し、公式サイトと地図へ進める。
- 完了イベントに `generation_id` / `trim_id` を追加。`dimension_basis` は `selected_trim` と `representative` を区別する。

## 検証

- 自動テスト15件成功。グレードの引き継ぎ、無効なID、制限データの欠損・不正値を含む。
- 全85記事の内部リンク検査、TypeScript、ビルドが成功。ESLintはエラー0、既存警告25件。
- ブラウザでPHEVの1,945mm・2,440kgが車種→施設で一致。施設では重量制限まで60kgの要確認判定を確認。
- 保存したPHEVがホームに引き継がれること、320pxで横はみ出しがないことを確認。
- ヘッダー検索の全角N-BOX、Escで閉じる操作、無効グレードの案内を確認。
- ブラウザ内でAPIの503を再現し、古い結果が消えること・再試行で復旧することを確認。
- 位置情報の実GPS取得、全記事の事実確認はこの改修の検証範囲に含めない。

## 運用

本番DBのデータ変更・マイグレーションはない。ソースをGit経由で反映する。
公開リポジトリのため、Tailwind Plus / Catalystのライセンスコードをコピーせず、既存のOSS部品を使用した。
プレビューのDB接続は作業ブランチ専用の暗号化設定。本番DBへの操作は読み取りのみ。
地図埋め込み用キーがない環境では外部地図リンクを表示する。
