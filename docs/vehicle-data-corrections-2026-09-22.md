# N-BOX 2代目の車両重量訂正（2026-09-22）

slave の自動照合（`tomepita-vehicle-verify`）で、N-BOX 2代目 JF3/JF4（前期型）の登録12件をメーカー一次資料と照合した。**4項目が一致した3件には出典と条件注記だけを付与し、車両重量が違う9件を本リリースで訂正した。** 全長・全幅・全高はすべて一致。

## 訂正内容

| グレード | 登録 → 公式（FF / 4WD） | 原因の見立て |
|---|---|---|
| L | 900 → **890** / 960 → **950**kg | 登録値は後期型（2020年12月〜）のLの値 |
| EX | 900 → **930** / 960 → **990**kg | Lの行と同じ値。前期・後期ともEXにこの重量は無く転記ミス |
| Custom L | 910 → **900**kg（FFのみ） | 登録値は後期型のCustom Lの値 |
| Custom L ターボ | 920 → **930** / 980 → **990**kg | 前期・後期とも該当値なし |
| Custom EX ターボ | 930 → **960** / 990 → **1,020**kg | 登録値は前期型のCustom L ターボの値（行ずれ） |

一次資料: [ホンダ N-BOX 主要諸元（2019年9月終了モデル）](https://www.honda.co.jp/auto-archive/nbox/2019/common/pdf/nbox_spec_list.pdf)。
2020年版アーカイブ（`auto-archive/nbox/2020/…/nbox_spec_list.pdf`）でも対象8グレードの車両重量が同じであることを確認し、条件注記の期間を「2017年9月〜2020年11月の前期型」とした。
列とグレードの対応はPDFの座標から機械的に対応づけて確認した（照合はClaude、訂正値は人が資料で再確認）。

重量は900〜1,020kgで、一般的な機械式駐車場の重量制限（1,700kg以上）に対する判定は訂正前後で変わらない。

## 今後の運用

slave の `tomepita-vehicle-verify` が毎日2世代ずつ照合する（2026-09-22 ユーザー承認）。

- 一致行: 出典と条件注記を付与し、空欄（最小回転半径・ミラー込み全幅）を補完する
- 食い違い: 別の照合で同じ資料を読み直し、同じ公式値になった行だけ自動で訂正する（出典・条件注記も同時に付与）。
  変更前の値は slave の台帳と `slave/data/tomepita/auto-corrections.jsonl`（本一覧と同じ要素形式）に残る
- 自動訂正しないもの: 差が大きい（寸法50mm超・重量100kg超）、乾燥重量、読み直しで値が割れたもの。
  これらは `correction-candidates.jsonl` と Slack に出るので、資料で確認してから本手順で訂正する
- 記事: 自動訂正のたびに、訂正前の数値を載せている記事を直して main へ push する。加えて slave の `tomepita-article-sync` が
  毎日2本ずつ、記事の数値を出典付き（確認済み）の登録値と照合して直す。どちらも行単位の編集案をコードで検証し
  （元の行の完全一致・表の列数・見出し不変など）、check:content と build を通してから push する
- DBの自動訂正は本一覧（初期データ補正）には反映されない。`auto-corrections.jsonl` を必要に応じて本一覧へ移す

同日、9/20 の監査で DB を訂正済みだった N-BOX 3代目 4WD（960→980kg）が記事3本に旧値のまま残っていたため手動で修正した（`98290a2`）。
